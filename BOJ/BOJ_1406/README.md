# BOJ 1406 - 에디터

## 1. 핵심 아이디어
- 문자열 전체를 매번 직접 이동시키지 않고, 연결 리스트의 iterator를 커서로 사용한다.
- 커서는 문자 위가 아니라 문자 사이를 가리킨다고 생각하면 `L`, `D`, `B`, `P`를 자연스럽게 처리할 수 있다.
- 삭제는 `erase`가 삭제 다음 위치의 iterator를 반환한다는 점을 이용해 커서를 안정적으로 유지한다.

## 2. 불변식 (Invariant)
- `cursor`는 항상 리스트 내부의 유효한 위치(문자 사이)를 가리키며, 리스트의 왼쪽 부분과 오른쪽 부분의 순서가 모든 명령 후에도 유지된다.

## 3. 시간 복잡도
- 시간: O(|초기문자열| + M)
- 공간: O(|초기문자열|)

## 4. 내가 한 실수 / 주의할 점
- 커서를 “문자 하나”가 아니라 “문자 사이 위치”로 해석해야 명령 처리가 꼬이지 않는다.
- `B` 연산에서 바로 현재 커서를 지우는 것이 아니라, 먼저 한 칸 왼쪽으로 이동한 뒤 삭제해야 한다.
- `erase` 이후 반환 iterator를 다시 커서에 반영하지 않으면 잘못된 위치를 참조할 수 있다.

## 5. 복습 질문 (Active Recall)
1. 왜 이 문제에서 배열/문자열 직접 삽입·삭제보다 연결 리스트 + iterator가 유리한가?
2. `cursor == begin()`일 때 `L`과 `B`는 각각 어떻게 처리되어야 하는가?
3. `erase`가 반환하는 값이 왜 중요한가?
4. 이 문제에서 커서를 “문자 사이”라고 보는 관점이 왜 핵심인가?
