# BOJ 5397 - 키로거

## 1. 핵심 아이디어
- 문자열을 직접 수정하지 않고, 커서를 기준으로 문자를 삽입/삭제할 수 있는 자료구조를 사용한다.
- `list<char>`와 iterator를 커서처럼 사용하면 `<`, `>`, `-`, 일반 문자 입력을 모두 O(1)에 처리할 수 있다.
- 각 테스트케이스마다 입력 문자열을 왼쪽부터 순회하면서 “현재 편집 상태”를 그대로 시뮬레이션하면 된다.

## 2. 불변식 (Invariant)
- 매 입력 문자를 처리한 뒤에도, `list`에는 현재까지 만들어진 비밀번호가 저장되어 있고, `cursor`는 항상 “문자가 삽입될 위치”를 정확히 가리킨다.

## 3. 시간 복잡도
- 시간: O(L) (테스트케이스 하나당, L은 입력 문자열 길이)
- 공간: O(L)

## 4. 내가 한 실수 / 주의할 점
- `erase(--cursor)`처럼 iterator를 이동시키는 순간과 삭제 순서를 헷갈리면 런타임 에러가 날 수 있다.
- 커서가 `begin()` 또는 `end()`일 때 `<`, `>`, `-`를 처리하는 경계 조건을 반드시 먼저 확인해야 한다.
- 문자열 중간 삽입/삭제가 많을 때 `string`으로 직접 처리하면 O(L^2)로 느려질 수 있으므로 자료구조 선택이 핵심이다.

## 5. 복습 질문 (Active Recall)
1. 왜 이 문제는 `string`보다 `list + iterator`가 더 적합한가?
2. 이 코드에서 `cursor`가 의미하는 위치는 정확히 어디인가?
3. `-` 입력을 처리할 때 왜 `cursor != begin()` 체크가 먼저 필요한가?
4. 각 입력 문자를 처리한 뒤 어떤 상태가 항상 유지되어야 하는가?
