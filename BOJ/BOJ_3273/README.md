# BOJ 3273 - 두 수의 합

## 1. 핵심 아이디어
- 배열의 원소를 앞에서부터 보면서, 현재 값의 보수인 `x - a[i]`가 이전에 등장했는지 확인한다.
- 이전에 나온 수들을 `check` 배열에 기록해 두면, 보수 존재 여부를 O(1)에 확인할 수 있다.
- 각 쌍은 “뒤에 나오는 원소를 볼 때” 한 번만 세어지므로 중복 카운트가 발생하지 않는다.

## 2. 불변식 (Invariant)
- i번째 원소를 처리하기 직전, `check[v] = true`이면 값 `v`는 `0 ~ i-1` 구간에 이미 등장한 적이 있다.

## 3. 시간 복잡도
- 시간: O(N)
- 공간: O(M) (`check` 배열 크기만큼, 값의 범위 기반)

## 4. 내가 한 실수 / 주의할 점
- `check` 배열 방식은 **원소 값의 범위가 작을 때만** 안전하게 사용할 수 있다.
- `x - arr[i] > 0` 조건은 입력 조건에 따라 의도가 맞는지 확인해야 한다. 0이나 음수도 가능한 문제에서는 틀릴 수 있다.
- 같은 수를 두 번 쓰는 경우가 허용되지 않도록, 반드시 **검사 후 현재 값을 체크**해야 한다.

## 5. 복습 질문 (Active Recall)
1. 왜 `check[arr[i]] = true`를 먼저 하면 안 되는가?
2. 이 풀이에서 중복 쌍이 세어지지 않는 이유는 무엇인가?
3. `check` 배열 풀이가 가능한 전제 조건은 무엇인가?
4. 값의 범위가 매우 커지면 어떤 방식으로 바꿔야 하는가?
